## Contraseñas

Una contraseña nunca se guarda ni se cifra: se guarda su hash, del que no se puede recuperar. `hashPassword` usa Argon2id con la configuración mínima que [recomienda OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html): 19 MiB de memoria, 2 iteraciones y 1 hilo.

```ts title="src/users/users.service.ts"
import { Injectable, inject } from '@vigajs/core';
import { hashPassword, needsRehash, randomToken, verifyPassword } from '@vigajs/crypto';
import { UsersRepository } from './users.repository.ts';

@Injectable()
export class UsersService {
  private readonly users = inject(UsersRepository);
  private readonly dummyHash = hashPassword(randomToken());

  async register(email: string, password: string) {
    return this.users.create({ email, passwordHash: await hashPassword(password) });
  }

  async verifyCredentials(email: string, password: string) {
    const user = await this.users.findByEmail(email);
    const valid = await verifyPassword(password, user?.passwordHash ?? (await this.dummyHash));
    if (!user || !valid) return undefined;

    if (needsRehash(user.passwordHash)) {
      await this.users.updatePasswordHash(user.id, await hashPassword(password));
    }
    return user;
  }
}
```

El resultado de `hashPassword` tiene un formato estándar, que incluye la sal y los parámetros, así que basta con una columna de texto:

```txt
$argon2id$v=19$m=19456,t=2,p=1$JXd7mQ0pW1i9wR0dNwQbyw$SjGh1rmvb4Br3Pq0C...
```

Fíjate en tres detalles del ejemplo:

- **`dummyHash`:** si el email no existe y respondieras de inmediato, el tiempo de respuesta revelaría qué emails están registrados. Por eso se calcula un hash también en ese caso.
- **`needsRehash`:** devuelve `true` si el hash se creó con otros parámetros. Como en ese momento tienes la contraseña en claro, puedes actualizarlo. Así, los hashes mejoran solos cuando viga sube sus parámetros.
- **`verifyPassword`:** devuelve `false` si la contraseña no coincide o el hash está mal formado, sin lanzar un error.

Las contraseñas se normalizan con NFKC antes del hash. Una `ñ` puede codificarse de dos formas según el dispositivo, y sin esto la misma contraseña no coincidiría.

### Protege el inicio de sesión

Cada hash ocupa 19 MiB y un hilo del pool de Node.js, que por defecto tiene 4. Mientras están ocupados, también esperan otras operaciones que los usan, como leer archivos. Por eso el inicio de sesión necesita un [límite de peticiones](../../security/rate-limiting/#por-ruta):

```ts
@Public()
@Post('/login')
@RateLimit({ max: 5, windowMs: 15 * 60_000 })
@Validate({ body: Login })
```

Valida también la contraseña con una longitud máxima en tu schema, como `z.string().min(12).max(128)`.

### Migrar desde bcrypt

No hace falta pedir a los usuarios que cambien su contraseña. Mantén tu librería de bcrypt durante la migración y actualiza cada hash cuando el usuario inicie sesión:

```ts
import bcrypt from 'bcrypt';

function checkPassword(password: string, stored: string) {
  return stored.startsWith('$2') ? bcrypt.compare(password, stored) : verifyPassword(password, stored);
}
```

Usa `checkPassword` en lugar de `verifyPassword`. `needsRehash` devuelve `true` con un hash de bcrypt, así que el código anterior lo sustituye automáticamente. Los usuarios que no vuelvan a entrar conservarán su hash de bcrypt: decide cuánto tiempo mantienes la librería y qué haces con ellos después.

## Tokens aleatorios

`randomToken` genera un valor impredecible para enlaces de recuperación, invitaciones o API keys. Guarda solo su hash, para que una filtración de la base de datos no permita usarlos:

```ts
import { hashToken, randomToken } from '@vigajs/crypto';

const token = randomToken();
await this.resets.create({ tokenHash: hashToken(token), userId, expiresAt });
await this.mail.sendResetLink(user.email, token);
```

Al recibirlo, busca por su hash, comprueba que no ha caducado y bórralo para que solo sirva una vez:

```ts
const reset = await this.resets.findByHash(hashToken(token));
if (!reset || reset.expiresAt <= new Date()) throw new BadRequestException('auth.invalidToken');
await this.resets.delete(reset.id);
```

`randomToken` genera 32 bytes por defecto y no acepta menos de 16. `hashToken` usa SHA-256, que aquí es suficiente porque el token ya es aleatorio. **No lo uses para contraseñas**, que necesitan un hash lento como `hashPassword`.

### Comparar secretos

`===` termina en cuanto encuentra una diferencia, y ese tiempo puede ayudar a adivinar un secreto. `safeEqual` tarda lo mismo sea cual sea el contenido o la longitud:

```ts
if (!safeEqual(req.headers['x-webhook-secret']?.toString() ?? '', this.config.WEBHOOK_SECRET)) {
  throw new UnauthorizedException();
}
```

## Las claves

Las URLs firmadas y el cifrado necesitan claves. Decláralas en el schema de [`@vigajs/config`](../config/), con un mínimo de 32 caracteres:

```ts title="src/config.ts"
export const Env = z.object({
  SIGNING_KEY: z.string().min(32),
  ENCRYPTION_KEY: z.string().min(32),
});
```

Genera cada una con:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

E importa `CryptoModule` en el módulo raíz. Es un módulo global, y solo necesitas las opciones de lo que uses:

```ts title="src/app.module.ts"
import { inject } from '@vigajs/core';
import { CONFIG } from '@vigajs/config';
import { CryptoModule } from '@vigajs/crypto';

CryptoModule.forRoot(() => {
  const config = inject(CONFIG);

  return {
    signingKeys: [config.SIGNING_KEY],
    encryption: { active: 'k1', keys: { k1: config.ENCRYPTION_KEY } },
  };
}),
```

viga no arranca si una clave tiene menos de 32 bytes, y el error nombra la clave sin mostrar su valor. Ese control solo mide la longitud: una frase como `mi-clave-secreta-de-la-empresa-2026` lo pasa, así que genera siempre valores aleatorios.

## URLs firmadas

Una URL firmada da acceso temporal a una ruta sin iniciar sesión, por ejemplo para descargar una factura desde un email:

```ts title="src/invoices/invoices.controller.ts"
import { Controller, Get, Public, inject, type HttpContext } from '@vigajs/core';
import { Signed, UrlSigner } from '@vigajs/crypto';

@Controller('/invoices')
export class InvoicesController {
  private readonly signer = inject(UrlSigner);

  @Get('/:id/link')
  link({ params }: HttpContext) {
    return { url: this.signer.sign(`/invoices/${params.id}/pdf`, { expiresInSeconds: 3600 }) };
  }

  @Public()
  @Signed()
  @Get('/:id/pdf')
  download({ params }: HttpContext) {
    return this.invoices.pdf(Number(params.id));
  }
}
```

`sign` devuelve la ruta con dos parámetros más:

```txt
/invoices/42/pdf?expires=1793577600&signature=Kq3vX0m...
```

`@Signed()` responde 403 si la firma no es válida o la URL ha caducado. La firma cubre la ruta, los parámetros, la caducidad y el método, así que no se puede cambiar `42` por `43` ni añadir parámetros. Por defecto, una URL firmada solo vale para `GET` y `HEAD`. Para otro método, usa `sign(path, { expiresInSeconds, method: 'DELETE' })`.

Para comprobar una firma sin `@Signed()`, usa `signer.verify(url, { method })`, que devuelve `true` o `false`.

:::caution
El enlace funciona para cualquiera que lo tenga hasta que caduque, y puede quedar en el historial del navegador o en los logs. Usa caducidades cortas y no lo uses para acciones que deban comprobar quién las hace. No se puede anular un enlace concreto: para eso, usa un [token guardado en tu base de datos](#tokens-aleatorios).
:::

Ten en cuenta también:

- **Firma la ruta que recibe el servidor.** Con `globalPrefix: '/api'`, firma `/api/invoices/42/pdf`, y si un proxy cambia la ruta antes de llegar a la app, la firma no coincidirá.
- **Solo se firman rutas**, sin dominio. Añade el dominio al construir el enlace: `` `https://mi-app.com${url}` ``.
- **`@Public()` es necesario** si el enlace se abre sin sesión. Sin él, la ruta exige autenticación además de la firma.

## Cifrado

Cifra los datos que tienes que recuperar, como las API keys de un proveedor que cada empresa configura en tu app. Si solo necesitas comprobar un valor, usa un hash.

```ts title="src/providers/provider-keys.service.ts"
import { Injectable, inject } from '@vigajs/core';
import { Encryptor } from '@vigajs/crypto';

@Injectable()
export class ProviderKeysService {
  private readonly encryptor = inject(Encryptor);
  private readonly keys = inject(ProviderKeysRepository);

  save(tenantId: number, apiKey: string) {
    const encrypted = this.encryptor.encrypt(apiKey, { context: `tenant:${tenantId}` });
    return this.keys.upsert(tenantId, encrypted);
  }

  async read(tenantId: number) {
    const encrypted = await this.keys.find(tenantId);
    return this.encryptor.decrypt(encrypted, { context: `tenant:${tenantId}` });
  }
}
```

`encrypt` usa AES-256-GCM y devuelve un texto que guarda qué clave se usó. Cifrar dos veces el mismo valor da resultados distintos:

```txt
v1.k1.Yp3Xb0mR2kQfVt8u.Hn2cJ9w4.9aX0qLm3Rt7KvB1sZc2YwQ
```

`decrypt` lanza un error si el valor se ha alterado, si no se puede descifrar con ninguna clave o si el contexto no coincide. El mensaje es siempre el mismo y no da más detalles.

**El contexto ata el valor a su dueño.** No se guarda en el resultado, pero tiene que coincidir al descifrar. Sin él, alguien con acceso de escritura a la tabla podría copiar la clave cifrada de otra empresa en la suya, y tu app se la descifraría.

Cifrar no sustituye a controlar quién accede a los datos: tu app descifra lo que le pidan, así que sigue comprobando los permisos. Tampoco puedes buscar ni ordenar por una columna cifrada.

:::danger
Si pierdes una clave de cifrado, pierdes todo lo cifrado con ella. Guárdala con el mismo cuidado que una copia de seguridad, y fuera de la base de datos que protege.
:::

## Rotar claves

Puedes cambiar una clave sin invalidar lo que ya existe.

**Para firmar**, pon la nueva primero. Se firma con la primera y se verifica con todas:

```ts
signingKeys: [config.SIGNING_KEY_NEW, config.SIGNING_KEY],
```

Quita la antigua cuando hayan caducado sus enlaces. Si una clave se ha filtrado, quítala de inmediato: sus enlaces dejarán de funcionar, pero nadie podrá crear más.

**Para cifrar**, añade la nueva con otro nombre y actívala. Se cifra con `active` y se descifra con cualquiera:

```ts
encryption: {
  active: 'k2',
  keys: { k1: config.ENCRYPTION_KEY, k2: config.ENCRYPTION_KEY_NEW },
},
```

Mantén `k1` hasta haber descifrado y vuelto a cifrar todos los valores que la usan. Para encontrarlos, busca los que empiezan por `v1.k1.`.

Cada valor usa un número aleatorio de 12 bytes, así que no cifres más de unos 4000 millones de valores con la misma clave: a partir de ahí, una repetición empieza a ser un riesgo real. Rota la clave mucho antes de llegar ahí.

## En los tests

Pasa claves de prueba reemplazando `CRYPTO_OPTIONS`:

```ts title="test/invoices.test.ts"
import { CRYPTO_OPTIONS, UrlSigner } from '@vigajs/crypto';
import { createTestingApp } from '@vigajs/testing';

const app = await createTestingApp(AppModule, {
  overrides: [{ provide: CRYPTO_OPTIONS, useValue: { signingKeys: ['k'.repeat(32)] } }],
});

const url = app.get(UrlSigner).sign('/invoices/42/pdf', { expiresInSeconds: 60 });
assert.equal((await app.request(url)).status, 200);
assert.equal((await app.request('/invoices/42/pdf')).status, 403);

await app.close();
```
